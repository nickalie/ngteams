# Endpoints: every request the project has seen or uses

This inventory combines dated web-client captures, native probes and the current `ngteams` implementation. The
protocol notes describe shapes and evidence; this file indexes them. Captures stay outside the repository, and all
IDs, host numbers, sites and tenant names below are placeholders. A dated held or denied request records what that
capture observed; it is not a current permission rule.

**Keep this current with endpoint changes.** Add a row in the service's table, describe the endpoint in our own
words, name its current native entry, and link its protocol evidence. An endpoint seen in a capture but not yet
reviewed stays **seen, not reviewed** until a note describes it. No participant classification or fence column is
part of this inventory.

## How to read a row

- **Path** is relative to the section's base; query strings list parameter names, never credentials or real IDs.
- **Native** names the current transport entry or receiving component. `Read`, typed requests/writes, `PostRead`
  and own-state calls go through the logged protocol transport. Calling writes use the calling service and
  tracker; typed delivery responses use `FrameSink::respond` on the delivery's own connection. `teams-auth` logs
  token/authz exchanges through the same debug wire logger. The sign-in window retains its host gate.
- **not used** means no native caller implements that operation; **no service** means the app's protocol transport
  has no service for it. Browser pages and their own requests are separate from the native transport.
- **Notes · task** links the shape/evidence and its implementation or capture milestone.
- **Evidence** distinguishes captured traffic, a native probe, native client traffic, bundle-only knowledge and
  connections that are not HTTP. Historic native probes used a retired client; current live tests use `ngteams`
  through `scripts/run-lab.sh` after the agent's [lab reach check](../lab-rules.md).

Every API request/response and both Trouter frame directions are recorded in full at debug, credentials redacted.
Info remains payload-free. The transport retains HTTPS-only, no proxy/redirect, service-specific credentials and
single-attempt typed writes; the outbox manages permitted retries and uncertain outcomes. There is no browser or
native write fence.

## Own-origin routing contract (inactive)

`teams_proto::Cloud` selects Microsoft or one validated HTTPS origin, including its TLS port. Microsoft remains
all existing constructors' default. No production account selects `Own` yet. The origin has no user info, path,
query or fragment. Service bases and discovered links must stay on that account's origin; Microsoft tokens must
never reach it. The transport's test-support loopback override runs only after the service URL has been validated.

Own servers use the same endpoint paths, queries, bodies, token audiences and headers below these bases,
except for the Trouter paths, handshake and calling domain described in its row, and the drive audience, which is
the own origin rather than a Microsoft SharePoint origin:

## Calling (`teams.microsoft.com/trap/`, `api.flightproxy.teams.microsoft.com/api/v2/`)

An Own account uses `/flightproxy/api/v2/epconv` for starts and retains every controller link, including its routing
query, under that origin's `/flightproxy/api/v2/ep/`. Both typed construction and transport refuse other origins
(including another TLS port). Its Trouter callbacks include `/trouter/`. Meeting codes build `/meet/<id>?p=<passcode>`
on that origin; cloud-aware calendar, thread, invitation and call-post readers reject foreign meeting/controller
links. Microsoft constructors and readers retain their default URLs and wire shapes.

Services behind the flight proxy are addressed as `ep/<service host>/…`, each URL handed out by the service. Typed call writes go through `Service::Calling` with the account's skypetoken; `teams-call` chooses actions and tracks invitations/callbacks, while `teams-core` shares the account call floor and sends through its outbox. Typed writes are single-attempt in the transport; the outbox manages explicit retry decisions and never blindly resends unknown outcomes. Calling delivery replies use the delivery's own connection.
